# /req — 요구사항 정리 이어가기

이 스킬은 여러 날에 걸쳐 새 대화에서 요구사항 정리를 이어가기 위한 것이다.
대상 문서: `docs/REQUIREMENTS.md`

## 시작할 때

1. `docs/REQUIREMENTS.md` 를 끝까지 읽는다. (`CLAUDE.md` 는 이미 컨텍스트에 있다.)
2. 사용자에게 짧게 현재 상태를 알린다:
   - 마지막 수정일
   - 확정(✅) 항목 수, 미정(❓) 항목 수
   - "9. 받아야 할 자료" 중 아직 받지 못한 것
3. 남은 ❓ 항목 중 **다음에 정할 질문 3~6개**를 주제별로 묶어 제시한다.
   - 다른 결정의 전제가 되는 질문(세대 구성, 부과 단위 등)을 먼저 묻는다.
   - 사용자가 `/req <주제>` 처럼 인자를 주면 그 주제의 질문부터 다룬다.

## 대화 중 규칙

- **코드는 절대 수정하지 않는다.** 수정하는 파일은 `docs/REQUIREMENTS.md` 하나뿐이다.
  - 코드에 영향을 주는 결정은 "부록 A. 기존 코드에 미치는 영향"에 기록만 한다.
- 사용자가 답할 때마다 **바로 문서에 반영**한다.
  - 정해진 내용은 ❓ → ✅ 로 바꾸고 결정 내용을 문장으로 적는다.
  - 새로 생긴 의문은 해당 섹션에 ❓ 로 추가한다. ID는 섹션 접두어(U, H, F, C, D, G, P)에 이어지는 번호를 붙인다.
  - 기존 ID는 바꾸지 않는다. 철회된 요구사항은 지우지 말고 ~~취소선~~ 과 사유를 남긴다.
  - 맨 위 "최종 수정" 날짜를 오늘로 갱신한다.
- 답이 모호하거나 서로 충돌하면 추측해서 확정하지 말고 되묻는다.
- 사용자가 파일(엑셀 양식 등)을 올리면 내용을 읽고, 거기서 확인되는 사실을 문서에 반영한 뒤 무엇을 반영했는지 알린다.
- 문서에 반영한 뒤에는 변경 요약과 다음 질문을 짧게 제시한다.
- 존댓말을 사용한다. 질문은 사용자가 번호로 답하기 쉽게 번호를 매긴다.

## 끝낼 때

- 사용자가 끝내자고 하면 이번 대화에서 바뀐 항목을 요약하고, 다음에 다룰 질문을 문서 "9. 받아야 할 자료" 또는 해당 섹션의 ❓ 로 남겼는지 확인한다.
- 커밋과 푸시는 사용자가 요청할 때만 한다.
